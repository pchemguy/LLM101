
# Defect Taxonomy / Codebook

## Классификатор дефектов введения диссертации для LLM-аудита

Это превращает ваш подход в **почти “промышленную систему анализа”**:

* стандарт → что проверять
* prompt → как проверять
* taxonomy → **как кодировать дефекты**

Теперь LLM может не просто “критиковать”, а выдавать:

* воспроизводимые,
* сопоставимые,
* машинно-обрабатываемые результаты.

---

## 1. Назначение классификатора

Классификатор дефектов нужен для:

* стандартизации критики;
* устранения размытых формулировок (“слабая цель”, “не очень хорошо”);
* накопления статистики дефектов;
* итеративной доработки введения;
* использования LLM как **инструмента диагностики**, а не “мнением”.

---

## 2. Общая структура кодов

Код дефекта имеет вид:

```text
[CATEGORY]-[NUMBER]
```

Примеры:

* GAP-01 — отсутствие исследовательского пробела
* GOAL-03 — цель сформулирована как процесс
* TASK-04 — задачи не ведут к цели
* NOV-07 — новизна тривиальна

## 5. Формат использования кодов в отчете

LLM должен не просто описывать дефект, а **привязывать код**.

Пример:

```text
MAJOR DEFECTS

1. GAP-02 — исследовательский пробел не сформулирован явно.
Текст описывает недостатки области, но не фиксирует конкретную научную проблему.

2. GOAL-03 — цель сформулирована как процесс.
"изучить", "проанализировать" без указания результата.

3. LOG-02 — задачи не ведут к цели.
Задачи описывают этапы работы, но не обеспечивают достижение заявленной цели.
```

---

## 6. Почему это критически усиливает LLM

Без кодов:

* LLM пишет эссе;
* сложно сравнивать результаты;
* сложно повторять анализ.

С кодами:

* появляется **дискретная система диагностики**;
* можно отслеживать улучшения между версиями;
* можно агрегировать статистику дефектов;
* можно обучать студентов на типовых ошибках.

Использовать так:

```text

+ Defect Taxonomy (this document)

+ Dissertation Introduction
```

И добавить инструкцию:

```text
For every detected defect:
- assign a defect code
- explain the defect
- quote or paraphrase evidence
```
